Portrait Touch Mapping Fix - Changes Summary
============================================

PROBLEM:
--------
In portrait mode (-90° rotation), touch coordinates were incorrectly mapped:
- Negative x-coordinates (e.g., -1161 instead of valid portrait coords)
- Off-screen values outside [0..1080, 0..1920] portrait bounds
- LoginScreen username/password fields not clickable
- Ghost touch areas in wrong locations

ROOT CAUSE:
-----------
Incorrect inverse transformation matrix composition. The old forward matrix
did not properly implement -90° rotation with letterboxing.

SOLUTION:
---------
1. Corrected forward matrix: M_fwd = T(ox,oy) · S(s) · T(0,Pw) · R(-90°)
   - Forward: xw = ox + s*v, yw = oy + s*(Pw - u)
   - Inverse: u = Pw - (yw - oy)/s, v = (xw - ox)/s

2. Added analytical mapping fallback (env: INPUT_ANALYTIC_MAP=1)

3. Enhanced diagnostics:
   - Startup logging of pipeline params (s, ox, oy, Pw, Ph)
   - Corner validation (4 portrait corners → window, 4 window corners → portrait)
   - Matrix vs analytical comparison
